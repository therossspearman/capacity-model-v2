### 3. 🔴 writeToProxy overwrites all workstream link fields, deleting workstreams that have no current assignments

- **File:** `frontend/components/modals/ProgramDetailModal.jsx`  **Lines:** 227-261  **Category:** bug  **Confidence:** high

### 2. 🟠 Scenario save silently truncates payloads larger than 270KB

- **File:** `frontend/components/optimization/ReprioritizationTab.jsx`  **Lines:** 1241-1250  **Category:** bug  **Confidence:** high

**Problem:** handleSaveScenario chunks the changes JSON into only three fields: Changes JSON (0..90k), of2 (90k..180k), of3 (180k..270k). Any content beyond CHUNK*3 (270,000 chars) is dropped with no error. Large portfolios with many priorityOrder entries + resourceAssignments + scoreBreakdowns can exceed this. The load path's truncation guard (lines 372-388) only fires when total length is an EXACT multiple of CHUNK and the tail does not end in '}', so most over-limit saves are not detected on load either — they parse-fail and are silently skipped (the catch at line 420 returns null). Net effect: a user saves a scenario, sees no error, and on reload the scenario is missing or partially corrupt. This is silent data loss.

**Fix:** Before slicing, compute Math.ceil(changesJson.length / CHUNK) and compare against the number of available Changes JSON fields. If it exceeds capacity, throw/alert a clear message (as the snapshot path already does at line 7317) instead of silently dropping the tail. Ideally reuse the same dynamic field-scan used for Results JSON to support N overflow fields rather than a hardcoded 3.
